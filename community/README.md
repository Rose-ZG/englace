# 英语信箱：共享社区接入

目前为可接入的社区实现，未配置共享数据库，不可声称已能跨用户收发。浏览器可保存草稿；发布和回信必须连接 Supabase 后使用。

## 管理员接入步骤

1. 创建独立 Supabase 项目，在 SQL Editor 执行 `community/schema.sql`（仅用于新库，执行前检查）。
2. Auth 设置启用 Anonymous Sign-ins。正式开放前配置 CAPTCHA／防滥用策略、项目预算、Auth 限流和内容举报处理；当前浏览器没有 CAPTCHA 集成，开启强制验证码后需补齐 UI，不能关闭防护来绕过验证。
3. 在 `community-config.js` 填项目 HTTPS URL 和 **publishable 或 anon 公钥**。绝对不能填写 secret/service_role 密钥；它会绕过权限，且该文件公开。
4. 对数据库权限做双用户验收：A 发布，B 开启会话，C 无权读取、发送该会话；B 无权撤下 A 的公开信；直接表读取应被拒绝。匿名会话刷新仍须指向同一 UID。
5. `node scripts/build-pwa.cjs` 后发布 gh-pages。公开社区需运营人员确认本部署地区的数据／内容管理要求。

## 权限和行为

- 无需邮箱或密码，但通过 Supabase 匿名 Auth 创建设备身份；名称仅是公开显示文字，不证明现实身份。
- 公开信正文与名称进入共享数据库。每人每天最多 5 封公开信、10 个新会话；每小时最多 30 条回信，限制由数据库函数执行。
- 每封信允许多个读者分别与作者建立独立一对一会话，同一读者重复回信沿用原会话。
- 四张表均启用 RLS，客户端无直接表权限；仅经授权 RPC 操作。函数用 auth.uid() 识别主体，不接受客户端自报 owner／sender。
- 私密回信仅会话双方和服务管理员可访问，**不是端到端加密**。服务请求不经过 GitHub Pages 缓存或离线缓存。
- 作者可撤下公开信。撤下不删除已经发出的私密回信；管理员可在数据库中处理举报。当前没有自动审核或实时推送。
- 清除网站数据或断开匿名身份可能永久失去旧会话访问权；原有公开信不会自动撤下。学习／工作室备份不包含社区身份和回信。
